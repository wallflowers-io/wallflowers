## WHAT WALLFLOWERS IS ##

WallFlowers is a peer to peer social network, open source at https://github.com/wallflowers-io/wallflowers under an AGPL license. It exists to be a positive example of search and social media, separate from the extractive practice of Meta, Google, and the Foundation Labs. The base artifact is the GroupObject. This is any addressable 'thing', and is simply an MLS group. Any member of an artifact is able to publish deltas which constitute the evolution of that thing, according to the ICD (core/coordination/delta-graph.icd.json). Identity is a private/public keypair.

### Core Usage ###

WallFlowers is accessed via an iOS app, a WebApp (mobile/desktop), and the CommunityAPI. The iOS app is fully end to end encrypted. The webapp cannot deliver notifications, which inhibits its utility.

The WallFlowers app is *one* instance of an app which utilises the interoperable standard of the GroupObject ICD. By publishing the ICD, the hope is that eventually, other platforms 

Q4 2026 will be spent finishing the iOS app. 

It is composed of three tabs: Red, Gold, Blue.
 - Red: Artifact Creation.
 - Gold: Messaging.
 - Blue: Artifact Collaboration.
 
On Red, you have the opportunity to create an Artifact. The degenerate case is a Note with no additional members, ie a GroupObject of type Note with its membership set containing only its creator. 

### WallFlowers Research ###

WallFlowers is intended to be used as a research platform, providing empirical data to the Digital Policy literature. This will be handled in a dedicated Research module on core, also AGPL, built to conduct robust user trials via A/B testing and other empirical methods.

## The two supported platforms **RHM**

WebApp - Keychain -> wallflowers hosted Door, running Node -> Authenticated client session
iOS - Keychain -> Persistent on device Node, fully e2ee

WebApp has desktop and mobile versions, which use the same core and rendering engine. For testing, always open the mobile version in the iOS simulator's Safari, and the web one in Chrome.

## Persistent State **RHM**

> **If it did not go through the MLS information architecture, it does not exist.**

The head, the recovery path and the ratchet are the **only** way state survives from one session to
the next, or from one device to another. Everything else — a JSON blob, a local table, a fixture, a
demo seed, an in-memory world, a `localStorage` key — is scaffolding that vanishes the moment a
person opens WallFlowers somewhere else.

WallFlowers is fundamentally a typed knowledge graph, where nodes are shared between many users via MLS. With a new browser or device, the user reconstructs their sovereign graph from seed, via their account spine and the relay. Nodes are called GroupObjects. Edges between GroupObjects are mutually defined as deltas in the respective GroupObjects, to form a triple.

A person's groups, their history, their membership and their ability to speak are all derived by
folding an ordered log of typed Deltas inside an MLS group whose roster **is** the access control. A
thing that was never a Delta was never in WallFlowers.

## The ICD is the source of truth for the model  **RHM**

> **`core/coordination/delta-graph.icd.json` defines the WallFlowers GroupObject/Delta model.
> Everything else references it. All alternatives are drift, and drift is an error.**

Not "a document that describes the model" — the document that *is* the model. The kinds, their
wire type ids, every op and its id, authority and commutativity: the ICD says, and code conforms.

**What this enables, concretely:**

- **Parametric Modelling.** To the greatest extent possible, numbers, counts, operations, should be read at build/runtime directly from the ICD, because copies break.
   ~/wallflowers/wallflowers_backup/product/core/docs/ref/ECSS_DATA_EXCHANGE.md is a useful reference for this, published by the European Space Agency. Read it.

*Parallel implementations of the delta model, including for testing, are expressly forbidden.*

** NEVER NERF A TEST **
Failing tests inform fixes or PRs. Weakening a test for a 'special case' or unimplmented stub breaks the test, and provides the false illusion of coverage.

## Build

- **The harness is `/Users/ralph/wallflowers/dev/ci.sh`** (private, Codeberg `wallflowers/dev`; its loop is `dev/ci.py`). Nothing else starts a runner. It starts Colima VM `wf-ci`, builds the image from `origin/main`'s `tools/ci/Dockerfile` (a change to `tools/ci` reaches CI once merged), serves queued `wf-ci` jobs, and stops the VM after `CI_IDLE` seconds with nothing queued. A push starts it (`make ci-hooks`); a second start exits at once.
- **Build happens on the VM.** CI's suites and the deploys' builds run there, GitHub Actions' only runner for this repository. Not on the Mac itself.
- **Exactly one harness.** One script, one VM, one build target. No session starts a second runner, VM, scaler or agent, nor runs a suite or a container on the VM beside the harness. Enforced: the harness deletes any runner it did not make, and the poke stops a `wf-ci` started without it.
- **Scale to zero.** No VM or runner persists between runs; only the minute poke (`dev/ci.sh poke`, launchd, `ci.sh install`), which starts the harness when GitHub has a job for it, from a push, a merge, a rerun or a dispatch. The VM's disk keeps the image and build caches.
- **In parallel, by measured memory.** Each job has its own label (`wf-ci-<job>`, `wf-ci-deploy-<route>`) and its own one-job container. A job is admitted while the peak memory its last runs measured fits beside what is running (`CI_HEADROOM` kept free); no history, or an OOM kill, and it runs alone. Longest first.
- **Measured and recorded.** Every job's memory, swap, CPU time, steps and lockfiles go to `CI_DB` (sqlite), read from outside the job. `dev/ci.sh report [job]` shows them, and `ci.log` names a job whose cost rose with what changed in its locks.
- **Contained.** Only pushes and dispatches of this repository by `CI_TRUSTED` are served, and the image's job-started hook (`tools/ci/job-started.sh`) fails anything else before a step runs. Deploys have their own caches; containers reach the internet only; each job has a time limit.
- **Settings:** `dev/.env` (gitignored; `dev/.env.example`). `CI_LOGS` (default `~/Library/Logs/wf-ci`) holds `ci.log`, `colima.log`, `ci.db` and `jobs/<runner>/`, kept `CI_LOG_DAYS`. `CI_CPUS`, `CI_MEMORY`, `CI_DISK` size the VM.
- A change to the harness, `dev/` or `tools/ci/`, is on Ralph's word.

## Deploy

`.github/workflows/deploy.yml`, from `main`, on the build VM. Each run waits for approval in the `production` environment, which holds the deploy key.

| Route | Ships | Restart |
|---|---|---|
| `arc` | the five planes → wallflowers-01; the account store when `arc/auth` changed | the planes; auth only when shipped |
| `door` | the Door → door-01 | every session ends |
| `app` | the webapp and its `/assets` → door-01 | none |
| `docs` | `app/door/docs/dist` → docs.wallflowers.io | none |

- `gh workflow run deploy.yml -f <route>=true`, then approve. `make live` reads what each box serves.
- Several at once ship arc, then door, then app.
- A change to `/v2/signin.js` moves its SRI: egregores-echoes.com's pin is updated in the same window.
- Never from a working tree. `make deploy-<route>` from a laptop only when the pipeline is broken, from a clean checkout of `main`, and said.

## If you are about to write something

- **Find the op first.** The catalogue is `core/coordination/delta-graph.icd.json`, and the
  reducers are held to IT by `core/pacific-core/src/icd.rs`. If the op you need is not there, the
  work is *adding an op to the ICD* — not storing the value somewhere convenient.
  
- **If you cannot persist it, say so and stop.** Report the gap. Do not fill it.

- **Small bugs: fix them, then report the fix in one line.** If you find an obvious defect while doing
  something else — a wrong tag, a stale comment, an off-by-one, a mis-scoped assertion, a dead
  reference — fix it in passing and say so. Do not spend a turn asking permission for the obvious.
  The boundary: anything that changes behaviour beyond the evident fix, or that edits code you did
  not come there to touch, is still a question.
