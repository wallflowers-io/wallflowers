Browser → phone

The browser stands up a real MLS identity, shows a signed contact bundle, and the phone scans or pastes it. That forms a genuine 1:1 connection group — the same handshake two phones use. Then a message typed here is sealed, published to the Arc's relay, and folded into the chat on the phone.

No multi-device, no device certs: the browser pairs as its own peer, which is the path that already works end to end.

What this page is not. The identity seed lives in this origin's localStorage, not behind the keyholder's non-extractable key, and MLS state is held in memory — a reload re-mints and you pair again. That is the persistence gap (SQLite/OPFS), deliberately not solved here.
