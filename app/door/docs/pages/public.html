Events and resources

A community's events and resources are published on its public page. Read them from anywhere, with no session: they're the same for everyone.

{{PUBLISHED_NOTE}}

mill-road above is the community's address, as in wallflowers.io/mill-road (:slug on Routes). A member's session can't read it: put it in your app's configuration, as signup showed it or as it was chosen at Register.

const { items } = await (await fetch('{{ARC}}/v1/face/mill-road/items')).json();
for (const [key, item] of Object.entries(items)) {
  if (key.startsWith('event:')) drawEvent(item);     // title, startMs, endMs, venue, descriptor
  if (key.startsWith('post:'))  drawResource(item);  // title, form, link, body, …
}
  • Items are keyed event:<id> and post:<id>, each with its op's arguments by the model's names, plus at.
  • An event given by dates alone runs from midnight to 23:59 on its last day: show dates, not times.
  • Read it when the page loads, and again when something changes (session.events, on a signed-in page). Never poll it faster than once every 30 s, and never in a loop: every community's page is served from it. On a server, keep it for a minute.
  • The pictures: {{ARC}}/v1/face/<address>/m/mark (also cover, logo, wallpaper).
  • If you link PDFs for WallFlowers' viewer, serve them with Access-Control-Allow-Origin: https://app.wallflowers.io.

Who sees them

In this release every event and every post is public: on the community's page, for anyone. The community's members also see them in WallFlowers, exactly as that page shows them: its events, where they can RSVP, and its newest 8 posts. For that, WallFlowers finds the community's page through its registered site, as yours is.

The model gives each event and post a visibility (private, connections or network; network when unset), but no route yet puts another member on an event's or post's roster, so private or connections would reach only its creator: leave it at network. Members-only events and posts, and co-hosts, are not yet available.
