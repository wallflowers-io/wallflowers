Where core differs by platform

  1. The words door (iOS): today it calls restore_identity, which brings back the identity only. That is the bug. After this PR it calls sign_in_from_words, which shares the passkey door's resume tail.
  2. Sealed state (Door only): a browser keeps nothing, so the Door reopens the device state it sealed (open_restored) before resuming. A phone keeps its own state, so it never needs this. This difference is by design.
  3. The head: core makes it (head_update), but only the Door publishes it. iOS never calls it.
